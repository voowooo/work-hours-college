# Work Hours Counter

Telegram Mini App для учета часов преподавателя (ДурневДН) по расписанию колледжа.

Вместо ручного ввода прихода/ухода приложение само читает расписание с сайта
[seimtc.by](https://seimtc.by), показывает уроки на выбранный день, отмечает
проведенные занятия и считает статистику «проведено / осталось».


## Как это работает

1. **Расписание.** По адресу
   `https://seimtc.by/images/raspisanie/{year}/{date}_{month}p.pdf`
   (например `.../2026/05_11p.pdf`) лежит PDF на день. Если файла нет, сайт
   редиректит на `.../ru/images/raspisanie/...`, где отображается `Error` —
   тогда день считается пустым. Из PDF берутся строки преподавателя
   `ДурневДН` и превращаются в пары: номер, группа, предмет, аудитория.
2. **Звонки.** У каждой пары есть время по таблице звонков (будни/суббота,
   Минск, UTC+3). Как только пара закончилась, она автоматически помечается
   как проведённая.
3. **Ручная отметка.** По клику на пару в календаре отметку можно поставить
   или снять вручную (перенос, отмена занятия). Ручная отметка имеет
   приоритет над авто-расчётом.
4. **Ручное добавление.** Кнопка «+ Урок» в календаре добавляет пару, которой
   нет в PDF: номер пары (только свободные), группа и предмет выбираются из
   уже известных списков, аудитория — по желанию. Такой урок помечен флагом
   `added`: он участвует в статистике и авто-отметке по звонкам, но следующая
   загрузка расписания его не удаляет; удаляется он крестиком в строке урока.
5. **Хранение.** Все уроки и счетчики пишутся в Supabase, поэтому даже если
   старые файлы расписания удалят на сайте, проведенные часы сохранятся.
6. **Уведомления.** Бот (`@wrkmtk_bot`) опрашивает Telegram (long-polling) и за
   15 минут до конца урока присылает сообщение: время конца текущей пары и
   данные следующего урока (начало, группа, предмет, аудитория). Под сообщением
   кнопка «🔕 Отключить до завтра» — уведомления глушатся до нуля часов
   следующего дня по Минску. Команды `/start` и `/stop` включают/выключают
   уведомления полностью; если боту запретили писать (403), уведомления
   отключаются автоматически.

## Supabase

1. Создайте проект в [Supabase](https://supabase.com).
2. Выполните SQL из `supabase-schema.sql`.
3. Скопируйте connection string в `backend/.env` (`DATABASE_URL`).

Основные таблицы:

- `users` — пользователи по `telegram_id`;
- `schedule_lessons` — уроки дня (`date`, `period`, `group_name`, `subject`,
  `room`, `conducted`, `manual`, `added`); строка сохраняется при успешной
  загрузке PDF и не удаляется, даже если файл расписания потом пропадет;
  `added = TRUE` — урок добавлен вручную и не вычищается при загрузке PDF;
- `subject_plans` — план часов по паре «группа + предмет»; пары создаются
  автоматически из расписания, часы задаются в настройках;
- `notification_settings` — настройки уведомлений (`enabled`, `muted_until`
  для кнопки «отключить до завтра»);
- в `schedule_lessons` поле `notify_sent_at` помечает, что уроку уже отправили
  уведомление (защита от повторов).

## Backend

```bash
cd backend
go mod tidy
export DATABASE_URL=postgresql://user:password@host:5432/dbname
export TELEGRAM_BOT_TOKEN=123456:ABC...   # токен от @BotFather, для уведомлений
go run cmd/server/main.go
```

Без `TELEGRAM_BOT_TOKEN` сервер работает, но уведомления отключаются.

### REST API

| Метод | Путь             | Назначение                                        |
|-------|------------------|---------------------------------------------------|
| GET   | `/schedule?date=YYYY-MM-DD` | Уроки ДурневДН на дату (PDF + сохраненное) |
| GET   | `/plans`         | План и число проведенных уроков по каждой паре    |
| PUT   | `/plans`         | Задать план часов для пары                        |
| PUT   | `/lessons/mark`  | Ручная отметка урока проведенным/непроведенным     |
| POST  | `/lessons/add`   | Добавить урок вручную (пара, группа, предмет, ауд.) |
| POST  | `/lessons/remove`| Удалить добавленный вручную урок                   |
| POST  | `/lessons/import`| Разовый перенос старых локальных отметок на сервер |
| GET   | `/notifications` | Текущие настройки уведомлений бота                 |
| PUT   | `/notifications` | Включить/выключить уведомления (включение снимает «до завтра») |
| POST  | `/notifications/test` | Отправить тестовое сообщение в Telegram       |

Запросы, связанные с пользователем, требуют заголовки
`X-Telegram-User-ID` и `X-Telegram-Username`.

Также есть GraphQL `POST /query` (пока только `me`).

## Экраны

- **Календарь** — неделя с счетчиками «проведено/всего», уроки выбранного дня
  со звонками и аудиториями, клик по паре — ручная отметка; кнопка «+ Урок»
  добавляет пару вручную (выбор пары, группы и предмета из списков), у
  добавленных уроков есть крестик удаления.
- **Статистика** — по каждой группе график «проведено / осталось», итоги.
- **Настройки** — сколько часов всего нужно провести по каждой паре
  (предметы подтягиваются из расписания автоматически) и уведомления бота:
  переключатель «Писать в Telegram» и кнопка тестового сообщения.
